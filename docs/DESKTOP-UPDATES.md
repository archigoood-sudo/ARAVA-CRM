# Обновления ARAVA CRM

## Как обновляется приложение

Установленные Windows- и macOS-версии ARAVA CRM проверяют опубликованные релизы GitHub вскоре после запуска и затем каждые четыре часа.

В Windows владелец может открыть «О программе», проверить новую версию, скачать её и отдельно подтвердить действие «Перезапустить и установить». Перед установкой CRM останавливает фоновые процессы и закрывает локальную базу данных.

На macOS приложение только проверяет наличие новой версии. Кнопка «Скачать новую версию» открывает по HTTPS DMG соответствующего GitHub Release. После загрузки владелец закрывает CRM, открывает DMG и вручную заменяет выбранную установленную копию приложения. `quitAndInstall` на macOS не используется.

Рабочие данные хранятся вне папки приложения. Обновление не заменяет базу SQLite, медиафайлы, резервные копии, настройки и идентификатор устройства.

## Файлы релиза

Windows использует NSIS-установщик, его blockmap и `latest.yml`.

macOS использует универсальный DMG для ручной установки. Универсальный ZIP, его blockmap и `latest-mac.yml` также публикуются стандартным `electron-builder`, чтобы приложение могло обнаружить новую версию через GitHub Releases. Неподписанная macOS-сборка никогда не передаётся в `quitAndInstall`: CRM открывает только фиксированный HTTPS-адрес DMG в официальном репозитории ARAVA CRM.

## Выпуск новой версии

1. Изменить версию SemVer одинаково в корневом `package.json`, `package-lock.json` и `apps/desktop/package.json`.
2. Выполнить все проверки, зафиксировать изменения и отправить `main`.
3. Создать тег с той же версией и отправить его:

   ```sh
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

4. Дождаться workflow «Desktop Release».
5. Проверить опубликованный GitHub Release. Он должен содержать NSIS-установщик, `latest.yml` и blockmap-файл из одной Windows-сборки.
6. Проверить универсальные macOS DMG, ZIP, blockmap и `latest-mac.yml`.
7. В установленной CRM нажать «Проверить обновления» либо дождаться автоматической проверки.

Обычный push в `main` запускает только Quality. Windows- и macOS-сборки Quality используют `--publish never`, сохраняются только как CI artifacts и не создают GitHub Release.

## Ручная установка macOS

Apple Developer membership в текущем процессе не используется. macOS-артефакты публикуются без Developer ID и нотариализации, поэтому автоматическая установка намеренно отключена. После загрузки DMG macOS может показать предупреждение о неизвестном разработчике; пользователь самостоятельно решает, разрешать ли запуск через стандартные средства Finder и настроек безопасности macOS.

Порядок ручного обновления:

1. В «О программе» нажать «Проверить обновления».
2. При наличии новой версии нажать «Скачать новую версию».
3. Проверить, что браузер открыл DMG в `github.com/archigoood-sudo/ARAVA-CRM`.
4. Закрыть ARAVA CRM.
5. Открыть загруженный DMG и вручную заменить именно используемую установленную копию `ARAVA CRM.app`.
6. Запустить приложение и проверить версию и сборку в «О программе».

## Установленная копия и артефакты сборки

Команды `npm run package -w @arava/desktop` и `npm run build:mac` создают артефакты только внутри репозитория. Возможные пути:

- `apps/desktop/release/mac/ARAVA CRM.app` — локальный артефакт обычной host-сборки;
- `apps/desktop/release/mac-universal/ARAVA CRM.app` — локальный универсальный артефакт;
- `apps/desktop/release/ARAVA-CRM-<version>-universal.dmg` — ручной установочный образ.

Эти файлы не копируются в `/Applications` и не запускаются package-скриптами. Наличие двух `.app` внутри `release` означает две сохранённые сборки, а не две независимые базы данных. Пользовательские данные продолжают храниться в `~/Library/Application Support/@arava/desktop/`.

Чтобы определить запускаемую копию, закройте CRM, откройте нужную `.app` вручную и сравните «Версия»/«Сборка» в «О программе». Удалять ненужную копию следует только после этого, перемещая в Корзину один конкретный `.app`; папку Application Support удалять нельзя.

## Доступ и безопасность

Публичный релиз использует встроенный `GITHUB_TOKEN` workflow; секрет GitHub не встраивается в приложение. Windows получает файлы через стандартный `electron-updater` и проверяет контрольную сумму из метаданных релиза. macOS renderer не получает URL, токены или локальные пути: main process открывает только заранее ограниченный HTTPS-путь официального GitHub Release.

SQLite, managed media, резервные копии, runtime-настройки и device identity находятся вне заменяемого application bundle и не удаляются при обновлении. Перед автоматической установкой в Windows CRM останавливает фоновые службы и закрывает SQLite. При ручной установке на macOS пользователь сначала самостоятельно закрывает CRM.
