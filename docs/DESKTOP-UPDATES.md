# Обновления ARAVA CRM

## Как обновляется приложение

Установленные Windows- и подписанные macOS-версии ARAVA CRM проверяют опубликованные релизы GitHub вскоре после запуска и затем каждые четыре часа. Проверка не скачивает и не устанавливает обновление автоматически.

Владелец может открыть «О программе», проверить новую версию, скачать её и отдельно подтвердить действие «Перезапустить и установить». Перед установкой CRM останавливает фоновые процессы и закрывает локальную базу данных.

Рабочие данные хранятся вне папки приложения. Обновление не заменяет базу SQLite, медиафайлы, резервные копии, настройки и идентификатор устройства.

## Файлы релиза

Windows использует NSIS-установщик, его blockmap и `latest.yml`.

macOS использует универсальный DMG для ручной установки, универсальный ZIP как обязательную полезную нагрузку Squirrel.Mac и `latest-mac.yml`. ZIP и метаданные должны быть созданы одной сборкой и опубликованы в том же GitHub Release. Приложение выбирает файлы через стандартный `electron-updater`; собственный загрузчик или установщик не используется.

## Выпуск новой версии

1. Изменить версию SemVer одинаково в корневом `package.json`, `package-lock.json` и `apps/desktop/package.json`.
2. Выполнить все проверки, зафиксировать изменения и отправить `main`.
3. Создать тег с той же версией и отправить его:

   ```sh
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

4. Дождаться workflow «Desktop Release».
5. Проверить опубликованный GitHub Release. Он должен содержать NSIS-установщик, `latest.yml` и blockmap-файл из одной Windows-сборки.
6. Если настроен подписанный macOS release, проверить универсальные DMG, ZIP и `latest-mac.yml`.
7. В установленной CRM нажать «Проверить обновления» либо дождаться автоматической проверки.

Обычный push в `main` запускает только Quality. Windows- и macOS-сборки Quality используют `--publish never`, сохраняются только как CI artifacts и не создают GitHub Release.

## Подпись и нотариализация macOS

Squirrel.Mac требует стабильную подпись приложения. Неподписанная или ad-hoc подписанная `.app` не является пригодной для надёжного самообновления. Первый update-capable выпуск должен быть подписан сертификатом **Developer ID Application** и нотариализован Apple. Ранее установленную неподписанную сборку потребуется один раз заменить вручную подписанным DMG; после этого последующие подписанные версии смогут обновляться автоматически.

Для включения macOS publish-job в GitHub необходимо:

- создать repository variable `MACOS_RELEASE_ENABLED=true`;
- добавить `MACOS_CSC_LINK` — экспортированный Developer ID Application `.p12` в поддерживаемом electron-builder формате;
- добавить `MACOS_CSC_KEY_PASSWORD` — пароль `.p12`;
- добавить `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` и `APPLE_TEAM_ID` для нотариализации.

Release-job использует `forceCodeSigning`, поэтому при неполной конфигурации он завершится ошибкой и не опубликует неподписанный macOS update. Локальные и Quality-сборки могут оставаться неподписанными только для проверки packaging; они не предназначены для реального self-update.

## Доступ и безопасность

Публичный релиз использует встроенный `GITHUB_TOKEN` workflow; секрет GitHub не встраивается в приложение. Клиент получает файлы только по HTTPS через стандартный `electron-updater` и проверяет контрольную сумму из метаданных релиза. Для подтверждения издателя Windows рекомендуется настроить сертификат подписи кода через защищённые GitHub Secrets.

SQLite, managed media, резервные копии, runtime-настройки и device identity находятся вне заменяемого application bundle и не удаляются при обновлении. Перед установкой CRM останавливает фоновые службы и закрывает SQLite тем же путём, что и Windows-версия.
