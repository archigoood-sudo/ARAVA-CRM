# Обновления ARAVA CRM

## Как обновляется приложение

Установленная Windows-версия ARAVA CRM проверяет опубликованные релизы GitHub вскоре после запуска и затем каждые четыре часа. Проверка не скачивает и не устанавливает обновление автоматически.

Владелец может открыть «О программе», проверить новую версию, скачать её и отдельно подтвердить действие «Перезапустить и установить». Перед установкой CRM останавливает фоновые процессы и закрывает локальную базу данных.

Рабочие данные хранятся вне папки приложения. Обновление не заменяет базу SQLite, медиафайлы, резервные копии, настройки и идентификатор устройства.

## Выпуск новой версии

1. Изменить версию SemVer одинаково в корневом `package.json`, `package-lock.json` и `apps/desktop/package.json`.
2. Выполнить все проверки, зафиксировать изменения и отправить `main`.
3. Создать тег с той же версией и отправить его:

   ```sh
   git tag v0.4.6
   git push origin v0.4.6
   ```

4. Дождаться workflow «Desktop Release».
5. Проверить опубликованный GitHub Release. Он должен содержать NSIS-установщик, `latest.yml` и blockmap-файл из одной сборки.
6. В установленной CRM нажать «Проверить обновления» либо дождаться автоматической проверки.

Обычный push в `main` запускает только Quality и не публикует релиз.

## Доступ и безопасность

Публичный релиз использует встроенный `GITHUB_TOKEN` workflow; секрет GitHub не встраивается в приложение. Клиент получает файлы только по HTTPS через стандартный `electron-updater` и проверяет контрольную сумму из метаданных релиза. Для подтверждения издателя Windows рекомендуется настроить сертификат подписи кода через защищённые GitHub Secrets до первого публичного выпуска.

Автообновление macOS в этой версии не включено: текущая локальная сборка не подписана и не нотарифицирована. Локальная упаковка macOS остаётся отдельным процессом разработки.
