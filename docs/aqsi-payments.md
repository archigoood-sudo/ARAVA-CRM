# Оплата через СБП на кассе aQsi

ARAVA CRM использует существующую физическую кассу aQsi. CRM создаёт локальную операцию оплаты, ARAVA-WEB передаёт команду кассе через официальный aQsi API, а клиент сканирует QR-код на экране кассы. Канонический `Payment` создаётся только в локальной CRM после подтверждённого результата aQsi.

## Настройка

На сервере ARAVA-WEB задаются переменные:

- `AQSI_API_KEY` — ключ внешнего API aQsi;
- `AQSI_BASE_URL` — по умолчанию `https://api.aqsi.ru/pub`.

Значение ключа не вводится в CRM и не передаётся на устройство. В «Настройки → Интеграция с сайтом → Касса aQsi» владелец выбирает физическую кассу из безопасного списка, полученного сервером.

## Официальный flow

1. `GET /v4/Devices` — доступные кассы.
2. `POST /v4/Slips/process/purchase` — команда `{ deviceId, amount, mode: "sbp_only", ttlMillis }`. `amount` передаётся целым числом копеек.
3. Ответ содержит только `operationId` и не означает успешную оплату.
4. `GET /v4/Operations/{id}` — проверка состояния.
5. Только `Completed` с операцией `acquiring.purchase` и slip `purchase`, совпадающими кассой и суммой, разрешает trusted finalization.
6. `POST /v4/Operations/{id}/cancel` используется только для незавершённых `Pending`/`Processing` операций.

Статусы aQsi сопоставляются так: `Pending` → ожидание, `Processing`/`Finishing` → обработка, `Completed` → успех, `Canceled` → отмена, `Timeout` → истёк срок, `Error` → ошибка.

## Безопасность и повторные запросы

Ключ aQsi хранится только в окружении ARAVA-WEB. В DTO и журнал попадают лишь безопасные идентификаторы операции, кассы и slip, сумма, статусы и время. Данные карты и держателя не сохраняются.

ARAVA `idempotencyKey` однозначно связывает локальную и серверную операции. Если ответ на стартовый POST потерян и безопасное восстановление не доказано, повторный POST в aQsi не выполняется: CRM сообщает, что состояние нужно проверить на кассе.

## Не входит в этот этап

Фискальный чек, ККТ/OFD, возврат успешной оплаты и автоматическая fiscalization не реализованы. Следующий этап сможет использовать сохранённые `Payment`, aQsi slip ID, device ID, сумму и время операции.
